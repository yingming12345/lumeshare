# 屏幕直播（局域网屏幕共享）

屏幕直播是独立于「局域网分享」的功能：把本机屏幕实时直播给同一局域网内的电脑或手机，
画面以 **WebM 视频流**（MediaRecorder 编码）在局域网内传输，不经过任何服务器。
直播发起方（主播）与观看方都需要在应用的「屏幕直播」页面开启该功能后才能使用。

## 端口

| 端口 | 用途 | 说明 |
| --- | --- | --- |
| `16900` | 网页直播服务 | 观看页面、房间码校验、流畅档视频流（2.5 Mbps） |
| `16901` | 高清视频通道 | 应用内观看与网页「高清」模式（10 Mbps） |

两个端口与局域网分享使用的 `16888`（HTTP）和 `17890`（UDP 发现）完全分开。
端口被占用时自动顺延到相邻端口，实际端口会写进直播地址与二维码，观看方无需关心。

## 地址与编码

- 直播地址：`http://<主播局域网IP>:16900/<令牌>`，令牌为 **38 位数字+字母混合**随机串，每次开播重新生成
- 房间码：**10 位纯数字**（首位不为 0），同样每次开播重新生成
- 令牌与房间码在画面流接口中等价，都可以作为 `key` 使用

## 视频流（真实视频，不是图片）

- 采集：Electron `desktopCapturer` 选择整屏或指定窗口，`getUserMedia` 获取原始屏幕流
- 编码：`MediaRecorder` 编码为 **WebM / VP8**（浏览器与 Electron 均原生支持硬件加速解码）
- 观看：浏览器原生 `<video>` + Media Source Extensions（MSE）播放，全屏 1080P，约 24 帧/秒
- 每个观看者拥有独立编码会话，都从关键帧开始，接入即可出画

### 流协议

响应体先写 4 字节标识 `LSV1`，随后是若干帧：`[类型(1)] [长度(4, 大端)] [负载]`
类型 `1` = JSON 元数据（mime / 分辨率 / 帧率 / 码率），类型 `2` = WebM 初始化段，类型 `3` = 媒体数据块。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 观看页面（未带令牌时显示房间码输入） |
| GET | `/<38位令牌>` | 观看页面（页面自动开始播放） |
| GET | `/player.js` | 播放器脚本（与应用内共用同一份实现） |
| GET | `/api/live/config` | `{app, running, hdPort, webPort, fps, viewers}` |
| GET | `/api/live/status` | `{running, startedAt, fps, profile, viewers, hdPort, webPort}`（不含房间码与令牌） |
| POST | `/api/live/check` | 请求体 `{code}`，校验房间码；成功返回 `{ok:true, token}` |
| GET | `/stream/<key>` | 流畅档视频流（端口 16900） |
| GET | `/hd/<key>` | 高清视频流（端口 16901） |

## 观看方式

- **网页端**：浏览器打开 `http://<主播IP>:16900/` → 输入 10 位房间码 → 观看；也可直接打开完整直播地址或扫码进入；支持流畅/高清切换、全屏、复制观看链接
- **应用内**：在「屏幕直播」页填写房间码与主播地址，或直接粘贴主播的直播地址；支持清晰度切换与全屏
- Windows 客户端**只生成二维码，不提供扫码观看**（没有摄像头扫码功能）

## 停止直播

点击「停止直播」、关闭「屏幕直播」开关或退出应用都会关闭两个端口并断开全部观看连接，
之前的链接与房间码立即失效。
